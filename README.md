# USB 继电器控制台（多设备 · 多窗口 · 全端口面板）

给 CUS/LCUS 型 USB 继电器模块（CH340 串口）做的图形化开关控制工具。
纯 Python 标准库实现，**不需要 pyserial、不需要联网、不需要编译**。

- **一个窗口同时显示所有继电器面板**：COM5、COM6…… 每台一张卡片，
  连接状态、开/关状态、通道、最后发送帧全部直接可见，**不需要切换当前设备**；
- **也支持多开窗口**：点“新窗口”或再双击一次启动图标，就能开第二个、第三个窗口；
- 每个窗口有自己独立的 `settings*.json` 配置和设备子集，互不覆盖；
- 同一个 COM 口同一时间只能被一个窗口连接（Windows 串口本身是独占的）。

## 快速开始

双击 **`启动继电器控制台.bat`**。主窗口会读取 `settings.json`，自动连接里面配置好的
COM5 和 COM6；每台继电器都会显示一张独立面板：

```
┌ 串口 [COM5▾]  波特率 [9600▾]  通道 [1]        [断开] [移除] ┐
│ [已开启]  累计 3 帧 · A00101A2        [开 ON] [关 OFF] [点动] [HEX] │
└─────────────────────────────────────────────────────────────────────┘
```

- 每张面板的 **开 / 关 / 点动 / HEX** 只作用于该面板对应的串口；
- 面板左侧色条和状态标签同时显示状态：
  - 绿色 **已开启**、蓝色 **已关闭 / 已连接**、橙色 **执行中 / 连接中…**、红色 **打开失败 / 通信异常**；
- 点多台面板的按钮互不影响，一台点动时另一台照样能操作；
- 点面板上的 **“连接 / 断开”** 控制该串口；
- 修改 **串口 / 波特率** 前先点“断开”，**通道** 可以随时改；
- **HEX** 打开该面板对应的原始指令窗口，方便试协议或控制别的型号；
- 工具栏的 **点动时长** 对所有面板生效；**+ 设备** 添加新串口，**刷新端口** 更新串口列表。

## 多窗口怎么用

1. 点工具栏的 **`新窗口`**，或者再双击一次 `启动继电器控制台.bat`；
2. 新窗口会自动使用 `settings-win2.json`、`settings-win3.json`……，
   设备列表首次从主窗口复制，窗口标题和标题旁的标签会显示 `窗口2`、`窗口3`；
3. **只有主窗口会自动连接；新窗口启动时所有面板都是“未连接”**，
   这是故意的——避免它去抢主窗口已经打开的串口；
4. 想让新窗口控制某台继电器时：
   - 先在当前持有该串口的窗口里点对应面板的 **“断开”**（或直接关掉那个窗口）；
   - 再到新窗口对应面板点 **“连接”**；
5. 窗口位置会自动错开，不会完全叠在一起。

例如“主窗口控制 COM5、窗口2 控制 COM6”：

```
主窗口：COM6 面板 → 断开（或移除 COM6 面板）
点“新窗口”：COM6 面板 → 连接
```

> 每个窗口的面板只操作本窗口已连接的串口。两个窗口同时显示 COM6 也没关系，
> 但同一时刻只有一个窗口能真正连上它，另一个点“连接”会提示被占用。

## 为什么以前开两个程序会冲突

Windows 的串口是独占资源，同一个 COM 口同时只能被一个进程打开；
而且旧版两个进程共用一份 `settings.json`，启动时都会去连里面记录的端口，关窗口时还会互相覆盖配置。

现在的做法：

- 一个窗口里所有设备面板同时显示，通常不需要多开；
- 多开窗口时，每个窗口写自己的配置（主窗口 `settings.json`，其它窗口
  `settings-win2.json`、`settings-win3.json`……），不会互相覆盖；
- 每个窗口配置用命名互斥体保护，同一个配置不会被两个进程同时打开；
- 串口仍然是独占的，所以一个 COM 口同一时间只让一个窗口连接，连接失败时会明确提示。

## 文件说明

| 文件 | 作用 |
| --- | --- |
| `启动继电器控制台.bat` | 双击启动，无黑色控制台窗口 |
| `relay_gui.py` | 图形界面（主程序，支持全端口面板 / 多窗口） |
| `relay_core.py` | 串口驱动 + 协议，可单独当命令行工具用 |
| `settings.json` | 主窗口配置：设备列表（串口/波特率/通道）、点动时长 |
| `settings-win2.json` 等 | 新窗口自动生成的独立配置（首次从主窗口复制设备列表） |
| `preview.png` | 界面截图 |

也可以用命令行启动：

```bat
python relay_gui.py                  :: 主窗口；主窗口已在运行则自动开新窗口
python relay_gui.py --new-window     :: 直接开一个新窗口（需手动连接）
python relay_gui.py --profile 工作   :: 使用指定配置 settings-工作.json（需手动连接）
```

快捷键：**F5** 刷新端口，**Ctrl+N** 新开窗口。

## 通信协议（已核对官方文档）

串口参数 **9600 / 8 数据位 / 无校验 / 1 停止位**，每帧 4 字节：

```
0xA0 | 地址码 | 操作码 | 校验码
        │        │        └── 前三个字节之和 & 0xFF
        │        └────────── 0x01 = 吸合(开)，0x00 = 释放(关)
        └─────────────────── 0x01 = 第 1 路，0x02 = 第 2 路 ……
```

| 动作 | 指令 |
| --- | --- |
| 第 1 路开 | `A0 01 01 A2` |
| 第 1 路关 | `A0 01 00 A1` |
| 第 2 路开 | `A0 02 01 A3` |

模块一般**不回传**数据，所以界面上的开/关状态是“最后发出的指令”，不是实测回读值 ——
如果用手按过模块上的按键，界面状态就会和实际不一致，点一下“关”再“开”即可校正。

## 界面功能

- **全端口面板**：每台继电器一张卡片，同时显示，不需要切换；每张卡片都有独立的
  连接、串口/波特率/通道、开/关/点动/HEX 和状态。
- **状态标签**：绿色“已开启”、蓝色“已关闭 / 已连接”、橙色“执行中 / 连接中…”，
  红色“打开失败 / 通信异常”；左侧色条同步变化；详情显示累计帧数和最后一次指令。
- **开 ON / 关 OFF**：直接给该面板对应的串口发指令，不受界面状态影响。
- **点动**：吸合工具栏设定的毫秒数后自动释放（默认 500 ms，可改成 50–10000）。
- **通道**：多路模块选 1/2/3……，单路模块保持 1。不同面板可以设不同通道。
- **原始 HEX**：点某台面板的 `HEX`，只给该串口发任意帧（回车发送）。
- **通信日志**：每帧收发都带时间戳，并用 `[COM5]` / `[COM6]` 标出是哪台设备，可保存成文件。
- 串口被别的软件或别的窗口占用、USB 没插好、找不到端口，都会在日志里给中文提示，
  且只影响那一台设备。

## 命令行用法

`relay_core.py` 自己就是个小工具，方便写进脚本 / 计划任务：

```bat
python relay_core.py --ports                     :: 列出所有串口
python relay_core.py --on                        :: COM5 第 1 路吸合
python relay_core.py --off                       :: COM5 第 1 路释放
python relay_core.py --port COM6 --on            :: 控制 COM6
python relay_core.py --pulse 1.5                 :: 吸合 1.5 秒后自动释放
python relay_core.py --addr 2 --on               :: 第 2 路
python relay_core.py --port COM5 --raw "A0 01 01 A2"
```

也可以在 Python 里调用：

```python
from relay_core import Relay

with Relay("COM5", address=1) as r:
    r.on()
    r.pulse(0.5)      # 点动 0.5 秒
    r.off()
```

命令行同样遵循“一个端口一次只能一个进程打开”，因此不要和图形界面的任何窗口
同时操作同一个 COM 口。

## 常见问题

**1. 某张面板显示“打开失败”/提示“被其他程序占用”**
这个端口正被占用。先检查：串口助手、SSCOM、Arduino IDE 串口监视器，或者
本程序另一个已经连上该端口的窗口。先在占用方点“断开”或关掉那个程序，再点“连接”。

**2. 点“新窗口”后，新窗口里的面板都是“未连接”**
这是故意的。新窗口不知道哪些端口已经被别的窗口占用，所以不会自动连接。
按“多窗口怎么用”的步骤，先在旧窗口断开对应端口，再在新窗口连接即可。

**3. 再双击启动图标，为什么没有提示“已经在运行”了**
现在允许开多个窗口。主窗口已经存在时，再双击会自动开 `窗口2`、`窗口3`……
每个窗口的配置独立，不会再互相覆盖。

**4. 只显示了一台继电器 / 没发现 COM6**
点工具栏的 `刷新端口`，再点 `+ 设备` 添加；也可以在对应窗口的
`settings*.json` 的 `devices` 数组里补一条
`{"port": "COM6", "baud": "9600", "addr": 1}`。

**5. 想换端口 / 波特率**
先在该面板点“断开”，再改串口/波特率；通道可以随时改。
修改会自动写进**当前窗口**的 `settings*.json`。

**6. 多个窗口的配置会互相覆盖吗**
不会。主窗口写 `settings.json`，新窗口分别写 `settings-win2.json`、
`settings-win3.json`……；用 `--profile 名称` 启动的窗口写 `settings-名称.json`。
只有两个窗口使用**同一个配置名**时才会被拒绝，并提示该配置已经在运行。

**7. 点开关没反应，日志却显示发送成功**
- 确认继电器板上的电源灯亮；
- 确认操作的是对应串口的面板；
- 确认模块地址（通道）和实物一致，单路模块用 1；
- 有的板子把地址码写死成别的值，用该面板的“HEX”发 `A0 02 01 A3` 之类试一下；
- USB 线只供电不传数据时，设备管理器里根本看不到对应 COM 口。

**8. 打开程序时继电器“嗒”了一下**
CH340 拔插/打开串口会拉低 DTR，个别板子会把这当成复位。程序里已加了 120 ms 延时再发指令，
一般不影响使用。

**9. 界面中文变成方块**
系统缺少“微软雅黑”，程序会自动退回 Segoe UI / 黑体。
